# Build Log

Chronological record of what was built, **why**, and which alternatives were rejected.
Read this for the story of the project, step by step.

| Step | What | Why / alternatives considered |
|------|------|-------------------------------|
| 1 | **Corpus acquisition** (`aiact.corpus.download`): the official English Official Journal XHTML of Regulation (EU) 2024/1689, from the Publications Office CELEX endpoint. Committed to `data/raw/` (1.26 MB). | EUR-Lex's HTML pages answer scripted requests with **HTTP 202 and an empty body** (bot challenge). The Publications Office serves the identical XHTML via content negotiation. The text is immutable, versioned law that EU reuse rules allow, so committing it makes parsing, tests and evals reproducible offline. Rejected: the PDF, where layout extraction loses the article, paragraph and point structure that citations need. |
| 2 | **Structure-aware parser** (`aiact.corpus.parse`) produces `data/corpus/ai_act.jsonl`: **306 provisions** (113 articles, 180 recitals, 13 annexes; 84.6k words) and **786 citable units**. Each article carries its chapter/section, title and numbered paragraphs, and each unit has a ready-made citation (`Article 5(1)`, `Article 3(44)`, `Recital 27`, `Annex III`). | Citations are the product, so the legal structure is kept from the start rather than guessed from chunks. Point labels (a), (b), (i) stay inline with their text on separate lines, so a chunk is quotable and citable down to `Article 5(1)(a)`. Article 3's 68 definitions become individual units, because that's how they're cited. |
| 3 | **Curated eval set** (`data/eval/questions.yaml`): **63 questions**. 55 are answerable, across definitions, prohibited practices, high-risk, GPAI, transparency, deployers, enforcement, scope and timeline. 8 must be declined. Each answerable question has gold citation units and a short reference answer. `test_eval_set.py` checks that every gold citation exists in the corpus and that key facts appear in the cited text. | The retrieval and answer metrics can only be as good as their labels, so the labels are checked against the law's text in CI. The declines mix off-topic questions ("capital of France"), other laws (GDPR, the US Executive Order) and near-misses the Act doesn't answer (registration fees, the current list of systemic-risk models), so refusal can't be gamed by keyword matching. Rejected: synthetic LLM-generated questions, because they echo the chunk wording and inflate recall. |
| 4 | **Retrieval stack choice:** Qdrant local mode, fastembed (ONNX, no torch) and tiktoken. | Qdrant gives dense, sparse (BM25 with server-side IDF) and RRF fusion in one `query_points` call. Local mode runs in-process for tests and CI, and the same code points at a Qdrant server in production. fastembed avoids a 2 GB torch install and runs on CPU. Rejected: FAISS plus rank_bm25, which means two indexes and hand-written fusion; Chroma, which has no native sparse vectors. |
| 5 | **Chunking + retrieval benchmark** (`chunking.py`, `index.py`, `retrieve.py`, `bench.py`). The grid is 3 chunkings (article / paragraph / fixed 256-token) × 2 embedders (bge-small / bge-base) × 3 modes (dense / hybrid RRF / hybrid + MiniLM cross-encoder), run on the 55 answerable questions. Results are in `data/bench/retrieval.md`. **Chosen: paragraph + bge-small + rerank.** It gets R@1 0.56, R@5 0.89, R@10 0.93 and MRR 0.712, with about 900 tokens of top-5 context. | Paragraph chunks with a "Article N - title (Chapter...)" header win at every setting. They beat fixed windows by 10–22 points at R@5, even though a fixed window carries ~3 citations and so is *easier* to score a hit on. They also give the LLM ~30% less context than article chunks. bge-base ties bge-small once the reranker runs (MRR 0.711 vs 0.712), so the smaller model stays (2× faster query embedding, ~3× smaller). Hybrid alone *lowers* R@1 versus dense on paragraph chunks (0.35 vs 0.51) but raises R@5. The reranker recovers top-1 precision and keeps the BM25 recall. Fast fallback: paragraph + bge-base dense (MRR 0.689 at 85 ms, vs ~5 s with rerank on CPU). |
| 6 | **Refusal threshold** from the same run: refuse when the top cross-encoder score is **< 2.36**. On paragraph chunks it answers 53/55 answerable questions and refuses 7/8 unanswerable ones. It's stored in `config.py` with the other chosen defaults. *Superseded by step 10* (1.37 after the retrieval fixes and a max-margin cut). | The cross-encoder logit is query–passage specific and comparable across queries. Dense cosine and RRF scores aren't: RRF depends only on ranks. Off-topic questions score from −11 to −4; most answerable ones score from +2 to +9. Caveat: it's tuned in-sample on only 8 negatives, so it's an operating point, not a measured refusal rate. The answer-level eval in milestone 3 will measure it end to end. Rejected: an LLM-only "is this answerable?" check, which costs an extra call per query. It stays as a second line for near-domain questions the threshold misses. |
| 7 | **CI** (`.github/workflows/ci.yml`). Lint and offline tests run on every push. A `retrieval-gate` job runs the production config with real models (cached between runs) and fails below `data/bench/baseline.json`. | The gate grades what users get, with real models on the real corpus, not fakes. Floors sit about one question below the measured values, because ONNX on Linux and on Windows can differ in the last float digits. The first Linux run passed in 4.5 minutes. Rejected: running the full 18-config grid in CI (~50 min), when only the shipped config needs protecting. |
| 8 | **Pluggable LLM client** (`aiact.llm`). It has one `complete(system, messages)` interface, chosen by `LLM_PROVIDER`:<br>• `anthropic`: `claude-sonnet-5-5`, cached system prompt, `effort=medium`, `fallbacks="default"`, `refusal` stop reason handled.<br>• `ollama`: qwen2.5:7b with `num_ctx=8192`.<br>• `fake`: a `ReplayLLM` cassette keyed by a hash of the full request. | Same design as RetailPulse. Answering is a single grounded call, so the interface is plain text with no tools. Sonnet over Opus: grounded QA over five short sources doesn't need the top model, and it's half the price. Ollama's default context would silently drop the system prompt once five sources are attached, so `num_ctx` is set explicitly. |
| 9 | **Grounded answerer** (`aiact.answer`).<br>• **Prompt:** the sources go into the prompt as `<source label="Article 5(1)">` blocks, and every claim must cite a label in brackets.<br>• **Validation:** citations are parsed and resolved against the sources. A narrower citation like `Article 5(1)(f)` resolves to its unit; `Article 50` never matches `Article 5`.<br>• **Repair:** one repair turn, used only if the draft is uncited or cites something outside the sources. Invalid citations are stripped before display.<br>• **Refusal triggers:** (1) top rerank score below the threshold, *before* any LLM call; (2) the model replies `INSUFFICIENT_EVIDENCE`; (3) the answer is still uncited after repair. | **Citations are verified in code, not trusted.** A citation is a claim about the law, so a fabricated "Article 6(2)" is worse than no answer.<br>**Refusal is layered from cheapest to most expensive.** The retrieval threshold catches off-topic questions for free. Near-domain questions, where the Act discusses a topic but not the specific fact (u04: "which models are on the systemic-risk list?"), pass retrieval, so the prompt has to catch them. The 4-question smoke test confirmed both layers.<br>**Rejected:** Anthropic's document `citations` feature. It returns char spans, not article numbers, and it isn't portable to Ollama. Also rejected: structured JSON output, which makes inline citations awkward to render and to check. |
| 10 | **Retrieval fixes from CHALLENGES #6:**<br>• **Chapter cross-references spelled out at chunk time** (`expand_chapter_refs`): "Chapters I (GENERAL PROVISIONS) and II (PROHIBITED AI PRACTICES) shall apply from 2 February 2025".<br>• **Recital rank prior** in rerank (`recital_penalty=2.0`), with refusal still using the *raw* top score.<br>Result on the production config: R@1 0.56 → **0.73**, R@5 0.89 → **0.95**, R@10 0.93 → **0.98**, MRR 0.712 → **0.834**. Files: `data/bench/production_p0.md` (expansion only: MRR 0.739, R@5 0.93) and `production_p2.md`. | Each fix was measured on its own:<br>• Expansion fixed the two timeline misses: Article 113 had never been in the 30 candidates, because it doesn't contain the word "prohibition".<br>• The penalty was chosen offline, by re-sorting saved candidate scores for p ∈ {0, 0.5, 1, 2, 3, 5, drop}. Most of the gain is already there at p=2. Dropping recitals entirely scores slightly higher (MRR 0.82 vs 0.80 offline), but it would lose the interpretive context answers can legitimately use.<br>**Caveat:** both were tuned on the eval set (one knob each). A held-out question set is the next step before claiming the gain generalizes.<br>**Note:** the full 18-config grid in `retrieval.md` was measured before these fixes. |
| 11 | **Max-margin refusal threshold.** `choose_threshold` now cuts mid-gap between the best split's boundary scores: **1.37**, between the highest refused unanswerable question (1.11) and the lowest answered answerable one (1.64). That answers 54/55 and refuses 7/8. | The previous rule put the threshold exactly on one answerable question's score, so any float jitter would flip it. The midpoint gives the most margin on both sides. With only 8 negatives this is still an operating point, so the answer eval measures it end to end. |
| 12 | **Answer eval with record/replay** (`aiact.evals.answers`).<br>• **Recording:** one real run saves a *retrieval snapshot* (`SnapshotRetriever`) and an *LLM cassette*. CI replays both for free in the test job, with no models.<br>• **Metrics:** answer rate, refusal rate, citation accuracy (cites a gold unit), invalid-citation rate in drafts, article-vs-recital citation rate, repair rate, latency and cost. | **Why snapshot retrieval too:** the LLM cassette is keyed on the full prompt, sources included. Replaying real retrieval in CI would let a last-digit ONNX difference between Linux and Windows reorder two sources, change the prompt and miss the cassette. Retrieval has its own gate (step 7), so the answer gate isolates generation plus the refusal logic.<br>**Scope:** these metrics are deterministic. Judged faithfulness and correctness (Ragas, LLM judge) come next. |
| 13 | **Docker** (CLI image) and the CI `docker` job.<br>• **Build:** `aiact.warmup` bakes the three ONNX models (~160 MB) and the corpus embeddings into the image. `HF_HUB_OFFLINE=1` is set after warm-up.<br>• **CI smoke test:** `docker run --network none … "What is the capital of France?"` must print `refused (low_evidence)`. | The container starts with no downloads. fastembed otherwise contacts the Hugging Face hub on every model load, even when the model is cached. The smoke test exercises real retrieval and the refusal gate offline, with no LLM or key. The HTTP API comes with the serving milestone. |
| 14 | **Recorded answer eval:** qwen2.5:7b via Ollama, 63 questions, ~70 min on a laptop CPU, about 75 s per answered question.<br>Results: **answer rate 0.96** (53/55), **refusal rate 1.00** (8/8), **citation accuracy 0.92** (49/53 answered cite a gold unit), invalid draft citations 0.02, cites an article/annex 0.96.<br>The cassette, the retrieval snapshot and `data/eval/answer_baseline.json` are committed, so CI's answer gate is now live. It replays in ~5 s with identical metrics. | **Why a free local 7B model first:** it gives a *floor* for generation quality at zero cost, and it proves the citation checks and the repair turn on a model that actually needs them (one draft cited outside its sources). The same harness records against `claude-sonnet-5-5` with `--provider anthropic` when a key is available.<br>**Refusal layers, from the trigger counts:** the retrieval threshold handled 7/8 unanswerable questions for free, and the prompt caught the near-domain trap u04.<br>**Remaining misses** (CHALLENGES #12): 3 from retrieval, 1 from the threshold, 2 from generation. |
| 15 | **Ragas judge bridge** (`aiact.evals.judge.RagasJudge`). It implements Ragas' modern `InstructorBaseRagasLLM` (`generate` / `agenerate`) on top of our `LLMClient`, with an optional `json_schema` that Ollama uses for constrained decoding. JSON is validated against Ragas' pydantic models, with one repair turn, then `JudgeError`. | Ragas' modern metrics need only this two-method interface. So judge calls reuse our providers *and* our cassette, and CI recomputes Ragas metrics for free. Rejected: `ragas.evaluate()` with LangChain or OpenAI wrappers, which bring more moving parts, no cassette, and OpenAI defaults. Two dependency surprises along the way, in CHALLENGES #13–14: the `langchain-community<0.4` pin, and the telemetry opt-out. |
| 16 | **Metric choice:** `Faithfulness` (statements vs retrieved sources) plus `AnswerCorrectness(weights=[1, 0])` (statement F1 vs the curated reference; no embedding term, so no extra model). Only answered, answerable questions are judged; refusals stay deterministic. | The two metrics cover the two failure modes citation checks can't see: claims beyond the evidence, and evidence-backed answers to the wrong thing. Rejected: answer relevancy, which needs embeddings plus generated questions and adds little given the gold citations. Context precision and recall were also rejected, because retrieval already has gold-citation recall@k. |
| 17 | **Judged recording:** qwen2.5:7b via Ollama, a stratified 20-question sample (`--sample 20`, seed 0, proportional by category). It was stopped at a time limit after **16 answers**: 80 judge calls, 0 parse retries, 0 failures. **Faithfulness 0.906, answer correctness 0.572.** `judged_baseline.json` pins those 16 ids, so CI replays exactly what was recorded. | **Why a sample:** ~5 min per judged answer on CPU makes the full 53 about 4.5 hours. A stratified sample keeps every category represented without hand-picking.<br>**Caveat:** the same model judges its own answers, so this is used as a regression gate, not a quality claim.<br>**Follow-ups:**<br>• Have the answer prompt restate the rule in full ("AI that filters job applications is high-risk under Annex III, point 4(a)") instead of "Yes [Annex III]". That's the h05 faithfulness miss.<br>• Re-record answers and judge with Sonnet / Opus when a key is available. |
| 18 | **Streaming as the single code path.**<br>• **Clients:** `LLMClient.stream()` yields text deltas, then the full `LLMResponse`. Anthropic uses `beta.messages.stream` with `text_stream`; Ollama uses NDJSON; the cassette replays recorded text as chunks and records streams into the same entries.<br>• **Answerer:** `Answerer.stream()` emits `retrieval → delta* → [repair → delta*] → final`, and `ask()` just consumes it. The refusal sentinel is buffered until the text can no longer be it. | **One path:** the CLI, evals and API all go through `stream()`, so a streamed answer can't drift from an evaluated one. The answer replay gate passed unchanged after the refactor.<br>**Deltas are a draft.** Citations can only be verified on the complete text, so `final` carries the verified answer (invalid citations stripped, or a refusal) and the client replaces the draft.<br>**Rejected:** buffering the whole answer before streaming. It's safe, but it throws away the time-to-first-token benefit, which is the reason to stream at all. |
| 19 | **Answer cache** (`aiact.cache.AnswerCache`).<br>• **Tiers:** exact match on the normalized question, then a guarded semantic match: cosine ≥ τ **and** identical discriminators. Discriminators are Article 3 defined terms (longest-first, plural- and "system"-tolerant), Article/Annex/point references and numbers.<br>• **Safety:** versioned by a hash of the prompt, retrieval config, corpus and model, so it never matches across versions. LRU plus a TTL.<br>• **Tuning:** on 40 labelled pairs (`data/eval/cache_pairs.yaml`, `aiact.evals.cache_bench`): 20 paraphrases and 20 look-alikes that swap one legal term. | **Measured, then mostly turned off.** Paraphrases score 0.79–0.96 and look-alikes up to **0.957** ("…reported" vs "…involving a death reported"), so the classes overlap:<br>• **Without the guard:** τ=0.80 serves 95% of paraphrases, but **13/20 look-alikes** get a wrong cached answer.<br>• **With the guard:** 4 false hits at τ=0.80. The guard catches provider/deployer, importer/distributor, real-time/post, point 4/5 and Article 5/50, but not words outside the lexicon ("death", "asylum").<br>• **Shipped:** τ=**0.96**, the lowest setting with zero false hits, which serves 5% of paraphrases. The exact tier does the real work, at **0.1 ms** per hit vs ~2.6 s p50 retrieval.<br>**Rejected:** a looser τ "for the hit rate". A wrong answer with valid-looking citations is the worst failure this product can have. |
| 20 | **HTTP API** (`aiact.api`): FastAPI with `POST /ask`, `POST /ask/stream` (SSE via sse-starlette), `GET /metrics` and `GET /health`.<br>• **Wiring:** a `create_app()` factory with an injectable answerer, as in RetailPulse.<br>• **Per request:** one JSON log line (cached, refused/reason, citations, top score, total ms, LLM calls, cost).<br>• **Metrics** (`aiact.metrics`): p50/p95 for total, retrieval, LLM and cached latency; cache hit rate; refusals by trigger; tokens; cost.<br>• **Concurrency:** the retriever holds a lock, because Qdrant local mode and the ONNX sessions are shared in-process. LLM calls still run concurrently. | **Latency is reported by stage**, because the stages differ by orders of magnitude, measured live:<br>• cache hit 0.1 ms;<br>• retrieval and rerank ~2.6 s p50;<br>• LLM: 183 s to first token for qwen2.5:7b on a loaded laptop CPU, almost all of it processing the ~2.1k-token prompt.<br>A single "p50 latency" would hide where to optimize.<br>**Rejected:** a Prometheus client dependency. JSON `/metrics` is enough for one process; at scale you'd use Prometheus histograms per replica. |
| 21 | **Docker serves the API** (uvicorn, one worker, HEALTHCHECK). The CI `docker` job runs two smoke tests: (1) `--network none`, where the CLI must refuse an off-topic question, proving the baked models load offline; (2) the live HTTP API, checking `/health`, a low-evidence refusal, an exact cache hit on the repeat, and `/metrics`. | Both run with no LLM and no key, because the refusal path never calls the model. Together they cover what a deploy needs: the image starts, models load without the network, the API answers, and the cache and metrics work.<br>**One worker on purpose:** the index lives in-process. Scale with replicas, or move to a Qdrant server shared by many workers. |
